# Autonode 3.0 路线图（依据信息架构评审）

> 依据：`Autonode_信息架构与运行逻辑评审_中文.md`（2026-11-18）
> 原则：先统一状态与操作语义，再拆模块；不引入数据库、不做多订阅同时加载、不接管 macOS 网络设置。

## 0. 3.0 的目标（一句话）

让用户能回答四个问题：

1. 当前哪个订阅真正生效？
2. 这条连接为什么走这里？
3. 自动选优为什么切 / 为什么没切？
4. 我的改动到底应用了没有？失败能不能恢复？

## 1. 四层模型（评审 §3）

```
资产层   订阅 → 节点 / 客户端分组
   ↓ 绑定
策略层   分流规则 → 目标分组；选优策略 → 候选与切换条件
   ↓ 编译 / 校验 / 应用
运行层   当前订阅 + 内核配置 + 分组当前选择 + TUN/VPN 接管状态
   ↓ 采样
观察层   连接、命中规则、出口链、测速、日志、诊断
```

| 对象 | 权威来源 | Autonode 权限 |
|---|---|---|
| 订阅清单 / 原始节点 | Verge + 订阅内容 | 只读；导入交给 Verge |
| 选优策略 / 规则草稿 / 地区覆盖 | Autonode | 持久化、校验、版本管理 |
| Autonode 生成的模板片段 | Autonode（Verge 载入） | 必须先退出客户端再写，保留他人内容 |
| Verge 生成的运行配置 | Verge | 只读 |
| 分组实际选择 / 连接 / 内核状态 | mihomo | 读取；支持切分组成员 |
| TUN / 系统代理 / 客户端生命周期 | 现有客户端与系统 | 观察与跳转；重启走协调器 |
| 系统 VPN / NE 应用 | macOS / 客户端 | 系统服务按能力连接；NE 只观察 |

## 2. 分阶段交付

### P0（3.0.0-alpha，本版本已做）

| 编号 | 交付 | 验收 |
|---|---|---|
| P0-1 | **统一 RuntimeSnapshot**：`GET /api/v2/runtime` 返回当前订阅、内核、TUN、分组当前选择、各源时间戳与新鲜度 | 概览与分组页共享同一快照；未知/过期/离线可区分 |
| P0-2 | **运行代次 epoch**：订阅切换、规则应用、服务重启时递增；Runner 提交前校验，旧任务不能再写 | 切订阅后旧任务提交被拒 |
| P0-3 | **配置 revision**：`config.json` 增加 `config_revision`；`GET/PATCH /api/v2/config` 带 revision，冲突返回 409 | 旧页面保存被拒绝并提示 |
| P0-4 | **健康样本分离**：`sub_health` 移到 `state/sub_health.json`，可丢失不污染配置 | 删掉该文件不影响配置 |
| P0-5 | **操作记录**：`state/operations.jsonl` 记录应用/切订阅/重启的阶段与结果 | 每个高影响操作可追溯 |
| P0-6 | **动作更名与分权**：纳管已有分组 / 创建客户端分组 / 重新发现 / 停止纳管；分流页拆「保存草稿」与「应用（重启内核）」 | 文案与行为一致 |
| P0-7 | **顶部全局上下文**：当前订阅 · 内核 · 模式 · TUN · 采集时间 | 每页顶部一致 |

### P1（3.0.0-beta）

| 编号 | 交付 | 验收 |

| P1-1 | 规则编辑器统一：域名/进程/IP 同一入口，显示顺序、来源、订阅范围、应用状态 | 合并后只读预览与实际配置一致 |
| P1-2 | 规则校验/预览：重复、遮蔽、提前 MATCH、目标不存在、跨订阅引用 | 冲突有明确提示 |

| P1-4 | 手动保持租约持久化：`state/checkpoint.json`，重启后恢复并校验成员 | 重启后保持有效；过期自动失效 |

| P1-7 | 导航重构：概览 / 策略 / 资源 / 网络 / 观察 | 旧 URL 兼容 |

## 3. 规则优先级（评审 §6）

三个顺序必须分开：

1. **接管顺序**：系统路由 → 是否进入 mihomo（TUN 排除、其他 VPN、应用代理）
2. **规则顺序**：进入内核后按有效规则决定动作
3. **组内选择**：命中分组后选哪个成员出口

3.0 不做隐式优先级：**类型与 role 不产生额外优先级**，顺序必须可见。

建议默认编排：

```
受保护例外（用户确认的局域网/企业目标）
用户自定义（域名/进程/网段混合，显式排序）
预设策略（AI 站点等，可展开、带版本）
订阅规则（保留原相对顺序，只读）
兜底 MATCH（仅在末尾有效）
```

## 4. 数据迁移（评审 §13.1）

1. 迁移前备份 config 与受管模板，记录 schema、时间、hash
2. 旧 `groups` 中能在当前控制器唯一解析的 → 当前订阅受管组
3. 无法判断来源的 → 「待绑定」，不自动关联
4. `custom_groups` 校验成员归属，缺失则保留定义不启用
5. `routes` 保留原顺序，无法解析的目标禁用
6. `sub_health` 移到状态仓库，格式校验、体积上限
7. `region_overrides` 逐步迁移到 NodeRef
8. 新配置不覆盖回旧 schema；降级用迁移前备份

## 5. 界面文案对照（附录 B 落地）

| 旧文案 | 新文案 |
|---|---|
| 添加分组 | 纳管已有分组 |
| 新建分组 | 创建客户端分组（需应用） |
| 扫描/同步分组 | 重新发现当前订阅分组 |
| 移除 | 停止纳管 |
| 当前出口 | 分组当前选择 |
| 保存并应用 | 保存草稿 / 应用（重启内核） |
| 应用分流 | 连接与应用 |
| 延迟未知 | 尚未探测 / 超时 / 过期（按因显示） |
| VPN 运行中 | 客户端进程运行中（连接状态单列） |
| 复制排除网段 | 复制建议列表（尚未应用） |
| 重启服务 | 重启 Autonode / 重启 Clash Verge |

## 6. 验收门槛（评审 §13）

| 阶段 | 门槛 |
|---|---|
| P0 | 能重现规则顺序与选优决策；读取不触发切换；旧任务无法在新上下文提交 |
| P1 | 编译顺序与实际配置一致；切换有理由与回读；跨订阅引用被拒绝 |
| P2 | 无证据显示未知；不新增未验证的 TUN/NE 控制能力 |

## 7. 不做的事

- 不引入数据库或微服务
- 不实现多订阅同时加载
- 不自建代理内核
- 不全面接管 macOS 网络设置
- 不承诺 NE 客户端（aTrust/EasyConnect/Shadowrocket）的登录与保活
